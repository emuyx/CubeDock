CubeDock 使用文档

CubeDock 把网易「本地联机」房间接到原生支持网易 RakNet v8 的 Bedrock 服务器。 本文覆盖安装、初始化、配置方案、账号与房间、代理/转服、资源包、房间管理和故障排查。

概览

CubeDock 不翻译游戏协议，而是负责登录链重签、Bedrock 加密握手、limbo/Transfer 和资源包处理。当前有两个连接模式：

  • 代理模式（推荐）：玩家流量经 CubeDock 中继到网易 RakNet v8 上游。
  • 转服模式：玩家先进入本地 limbo 虚空世界，预加载资源包并显示表单，再直连目标服务器。

当前版本还提供多配置方案、每账号独立房间 runtime、账号仪表盘、房间侧踢人、房间标签、 准入等级、网易房间成员列表、手动好友申请和第一方认证链。

版本提示：本站对应 main 分支的 v0.3.1 开发版； Releases 中的最新稳定版仍是 v0.2.0。下载按钮始终指向最新稳定版。 GitHub Actions 的测试版构建 会保留每次 main 推送的构建产物，适合提前试用，但不保证稳定。

运行要求

项目要求
客户端网易互通版 3.10（默认房间版本 1.21.130.0，协议 43）
上游服务器必须原生支持网易 RakNet v8；标准 BDS 不能直接使用
转服模式客户端能直连目标服务器；资源包需与 limbo 预加载一致，且未加密、静态
运行平台Windows / Linux / macOS
从源码构建Go 1.26+（会自动使用 1.27.3 工具链）与 Node.js 24
不要使用标准 BDS：代理和转服都要求上游支持网易 RakNet v8。 转服模式只是让客户端直连目标，不会把网易协议转换成标准 Bedrock。

安装与首次启动

  1. 下载发布包

    从 Releases 下载对应系统的压缩包并解压。

  2. 运行程序

    Windows 双击 CubeDock.exe；Linux / macOS 在终端运行解压出的程序，必要时先 chmod +x。

  3. 创建管理员

    首次启动会在终端显示控制台地址并打开浏览器。默认 http://127.0.0.1:18321/；首次进入时创建管理员账号和密码。初始化只允许本机，远程访问者不能抢占。

  4. 完成设置向导

    按页面提示完成连接设置、添加账号、运行预检和开始房间；还没有配置方案时，先到「配置方案」页创建。无头环境可用 CUBEDOCK_ADMIN_USERNAME / CUBEDOCK_ADMIN_PASSWORD 仅做首次初始化。

数据文件：config.json（全局设置 + 配置方案）、 room-tokens.dat、accounts.json（含 profile_id）、 interop-device.dat、admin.json、logs/。 Windows 使用 DPAPI，其他平台使用 0600 权限；不要提交或分享这些文件。

方案、账号与房间

三者关系可以简单理解为：

  • 配置方案保存一套服务器、房间、资源包和 limbo 表单设置；
  • 网易账号在添加时选择一套方案，并获得独立的房间 runtime；
  • 房间是账号的运行时状态，可以单独启动、停止和重连。

一个账号只能有一个房间；多个账号可以共用同一方案，也可以使用不同方案。 切换账号的方案需要先停止全部房间，切换后下次启动该账号的房间时生效。

批量管理：「主页」的全局启动/停止作用于全部账号； 单账号操作在「账号与房间」或侧边栏账号入口的仪表盘中完成。

配置方案

在「配置方案」页新建、复制或删除方案。方案分为四个标签页： 「连接」「房间」「资源包」「提示页面」。有房间运行时，方案设置不可修改。

连接

字段说明
方案名称用于在账号和仪表盘中识别
连接方式代理模式（推荐）或转服模式（先进中转房间）
服务器地址IP:端口，例如 127.0.0.1:19132；必须支持网易 RakNet v8。转服模式下这是最终目标服务器
中转房间监听地址/端口仅转服模式显示；每个转服方案使用独立端口，一般保持 127.0.0.1
房间协议版本默认 43；只有确认客户端或服务器版本变化时才需要改

房间

字段说明
房间名称 / 密码显示在网易「本地联机」列表中；密码可选
房间总人数包含 CubeDock 房主账号
房间版本默认 1.21.130.0
掉线重试间隔房间掉线后等待多少秒重连
准入等级限制可加入的玩家等级；0 表示不限制
房间标签最多 3 个，例如生存、创造、建筑等
仅好友可见 / 自动同意好友 / 允许 PvP控制房间准入和游戏内 PvP
开启「仅好友可见」时，CubeDock 会跳过「自动同意好友申请」，避免陌生人通过好友申请进入房间。

资源包

设置资源包目录，并选择开房时是否自动从服务器拉取。代理模式不使用本地资源包； 转服模式会由 limbo 预加载并处理资源包。加密或动态生成的资源包当前不支持。

提示页面

仅转服模式使用：设置 limbo 表单的标题、内容和按钮文字。玩家点击按钮后通过 Transfer 进入目标服务器。

账号与登录

进入「账号与房间」→「添加网易账号」。添加前需要先停止全部房间，因为重新登录可能 使正在使用的会话失效。

  • 邮箱直登：使用互通版邮箱和密码，走 a50 / x19 / uni_sauth 链路；
  • 导入 sauth：粘贴已有的互通版会话凭据，适合高级用法；
  • 配置方案：每个账号在添加时选择一套方案；
  • 更新登录：凭据过期后，在账号页点「更新登录」，用邮箱密码或新的 sauth 重新登录。
1351 安全验证：登录时若提示需要安全验证，点击页面上的「打开网易验证页面」 完成验证，再回到 CubeDock 点一次「登录并添加」。CubeDock 不会自动重试。

同一网易账号不能同时开两个房间。账号数量不设固定上限，实际数量受机器资源与网易限制。

开房与仪表盘

点击「账号与房间」列表中的账号，或侧边栏「我的房间」中的账号，进入该账号的仪表盘。 仪表盘提供：

  • 房间状态：启动、停止、重连，以及当前阶段和房间号；
  • 在线玩家 / 在线时间 / 连接方式 / 服务器；
  • 配置方案：查看当前方案，或切换到其他方案（需先停止全部房间）；
  • 资源包：查看目录、包数量，或从服务器拉取；
  • 好友申请：房间运行时读取待处理申请并手动同意；
  • 诊断：只读检测该方案配置、服务器、中转房间和资源包，不会登录网易账号；
  • 房间日志：按房间过滤事件、搜索和导出；完整日志在「控制台」页。

房间进入 online 后，房间号会显示在「本地联机房间」卡片中。手机在网易版 Minecraft 客户端打开「本地联机」，刷新后即可加入。

流量路径玩家 → CubeDock → 上游玩家 → limbo → 目标服
上游要求原生支持网易 RakNet v8客户端可直连；资源包需匹配

资源包由上游处理limbo 预加载，仅未加密静态包

推荐场景长期生产 · 兼容网易上游大厅入口 · 静态包 · 真实 IP

房间与玩家管理

代理模式下，玩家弹窗提供两个标签：

  • 已进入世界：已完成上游登录、进入世界的玩家；可断开其本地连接；
  • 网易房间成员：TanLobby 房间成员，包含已进房但尚未进入世界的玩家；可按房间玩家 ID 踢出。

房间侧踢人通过 TanLobby 控制通道发送，并立即断开本地 NetherNet 连接。踢出依赖 dockerB transfer 节点（SignalWebPort 8900）；dockerA 可以开房和设置标签，但不处理踢出。CubeDock 会自动优先选择 dockerB。

踢出不等于封禁：被踢玩家仍可能重新加入。若需要持续限制，可配合 「仅好友可见」、房间密码或准入等级。

房间标签最多 3 个；标签和准入等级在配置方案中设置，保存后重新启动房间生效。 TanNewGuestResponse 不携带游戏名，因此等待中的成员显示为 房间玩家 <ID>。

好友申请

配置方案可以开启「自动同意好友申请」；开启「仅好友可见」时自动同意会被跳过。 如果关闭自动同意，房间运行后可以在账号仪表盘的「好友申请」卡片中读取待处理申请， 并逐个手动同意。

好友申请使用运行中房间保存的完整房间加密密钥；若凭据过期，需要先更新登录再启动房间。

控制台命令

命令说明
help显示帮助
list玩家 ID、名称、房间、状态、在线时长、上下行包数
kick <ID|名称>断开指定玩家；名称含空格时加引号
transfer <ID|名称> <host:port>代理模式下注入 Transfer（POC）

转服模式的玩家已交给中转房间/目标服务器，CubeDock 不再提供世界玩家管理。

HTTP API

除登录页、静态资源、/api/login、/api/setup/status 和 /api/setup 外，其余页面与 API 都需要管理员会话。完整端点表见 README。

  • 全局：/api/status、/api/start、/api/stop、/api/config；
  • 单账号：/api/room/start、/api/room/stop、/api/room/restart；
  • 方案：/api/account/assign-profile、/api/packs?profile_id=、/api/diagnostics?profile_id=；
  • 房间：/api/room/members?index=、/api/room/kick-member；
  • 好友：/api/friends?index=、/api/friend/accept。

/api/session/* 只允许本机访问；控制台只允许白名单 Host/Origin。

诊断与日志

「诊断」页和账号仪表盘的诊断都是手动检测，不会登录网易账号。检查项包括方案配置、 服务器连通性、中转房间和资源包。诊断报告已脱敏，可直接复制。

  • 房间日志按账号过滤，支持搜索和导出；
  • 完整事件在「控制台」页；
  • 调试日志只记录消息来源/类型和刷新阶段，不输出 SDP、candidate、TURN 凭据或房间 token；
  • 备份包含配置方案、全局设置和账号信息，不包含网易登录凭证。

数据与安全

  • 控制台默认监听 0.0.0.0:18321，默认 HTTP 不加密；
  • 敏感环境请限制为可信网络，跨不可信网络使用 SSH 隧道或 HTTPS 反向代理；
  • 管理员密码使用 bcrypt 保存；Cookie 为 HttpOnly、SameSite=Strict、12 小时；
  • 首个管理员初始化只允许 loopback；登录有按 IP 的限速；
  • 网易会话保存在 room-tokens.dat：Windows 使用 DPAPI，其他平台 0600；
  • admin.json 不使用 DPAPI；不要提交或分享任何数据文件；
  • 认证链由第一方 internal/netease 实现，不再包含 AGPL 组件。

更多部署边界见 SECURITY.md。

故障排查

手机看不到房间 / 开房失败

确认账号可以正常登录、没有在其他设备上登录，房间已经显示为在线。若返回 1351， 打开验证链接完成验证，再回到页面点一次「登录并添加」；CubeDock 不会自动重试。

玩家进房后马上断开

先检查服务器是否支持网易协议、版本是否接近、资源包是否一致；转服模式还要确认 玩家能直连服务器。仍失败时在诊断页复制报告。

资源包不下载 / 转服时报资源包错误

网易客户端会忽略 ResourcePacksInfo，limbo 默认用 netease 模式强制 SendPacks， 并在最后一包后补发 Stack。确认资源包目录正确、包与目标服务器一致；加密包/动态包 不支持。ResourcePackStack 后主动断开是拉包流程的预期行为。

控制台打不开 / 忘记管理员密码

默认地址是 http://127.0.0.1:18321/。初始化只允许本机。忘记密码需 停止程序、备份并删除数据目录中的 admin.json，重启后重新创建。没有远程 或命令行重置入口。

房间踢人生效，但玩家又回来了

房间踢出不封禁；请确认 transfer 节点是 dockerB，并配合仅好友、密码 或准入等级限制。若被踢玩家仍在等待成员列表，可再按其房间玩家 ID 踢出。

等待中的房间成员没有名字

TanNewGuestResponse 不携带游戏名，未进入世界的成员显示为 房间玩家 <ID>。进入世界后会和玩家注册表合并显示名字。

多账号并发、Linux/macOS 和资源包的限制

>8 账号真实并发、Linux/macOS 实机、go test -race、 WebUI 移动端专项和非 Windows 管理员登录仍未覆盖；加密/动态资源包当前不支持。 公开分发前仍建议对 vendored solver 做许可复核。
