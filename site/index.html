FEATURES

从登录到进服，一条完整链路

不做协议翻译，只做网易客户端与兼容上游之间的必要握手和转发。

互通版邮箱直登

用网易邮箱和密码走 a50 / x19 / uni_sauth 链路换取互通版会话，无需抓包或手动导入 Cookie。

第一方认证链

PE 认证、用户资料、transfer 节点和房主凭据由 internal/netease 实现；不再依赖 AGPL 组件，发布包也不再生成 SOURCE/。

加密中继

为每个连接生成 P-384 密钥，重签单段登录链并代客户端完成 ECDH / AES-CTR 握手，游戏包原样转发。

limbo 转服

本地虚空世界、SimpleForm、关闭后重开；点击按钮通过 Transfer 直达目标服务器，目标看到真实 IP。

资源包

强制 SendPacks、Stack fallback、最后一包后补发；支持本地 UUID+版本跳过、去重和未加密包拉取。

配置方案 + 账号仪表盘

服务器、房间、资源包和 limbo 表单按方案保存；每个账号独立启动、停止、重连，并在仪表盘查看玩家、好友申请、资源包、诊断和日志。

多账号 / 多房间

可添加多个网易账号，不设固定数量上限；每个账号一个本地联机房间和独立 runtime；代理模式下提供真实玩家注册表、稳定玩家 ID 和 list / kick 控制台命令。

房间管理

房间侧踢人、最多 3 个标签、准入等级和网易房间成员列表；等待中的玩家也能按房间玩家 ID 踢出。

好友申请

支持自动同意；运行中的房间可以在账号仪表盘读取待处理申请并手动同意，配合「仅好友可见」控制准入。

CONNECTION MODES

代理还是转服？按目标场景选

代理模式是默认主路径；需要 limbo 大厅、预加载静态资源包或让目标看到真实 IP 时使用转服模式。

默认 · 主路径

代理模式

玩家流量经 CubeDock 中继到上游，登录链由 CubeDock 重签，游戏包原样转发。

玩家→CubeDock→网易 RakNet v8 上游

适合

  • 上游原生支持网易 RakNet v8
  • 希望长期稳定中继、减少客户端网络要求
  • 需要上游看到网易身份
  • 不想额外运行 limbo

不适合

  • 标准 BDS 或只支持国际版协议的上游
  • 希望目标服务器直接看到玩家真实 IP
延迟更低 · 不长期占用目标连接 · 生产主路径
limbo + Transfer

转服模式

玩家先进入本地 limbo 虚空世界，预加载资源包并显示表单；点击后客户端直连目标服务器。

玩家→limbo→目标服务器

适合

  • 客户端能直接访问目标服务器
  • 目标资源包未加密且静态
  • 希望目标看到真实 IP / 延迟
  • 需要 limbo 大厅或表单入口

不适合

  • 加密 / 动态资源包
  • 目标资源包与 limbo 预加载不一致
  • 客户端无法直连目标
真实 IP · 资源包前置 · 只覆盖未加密静态包
维度 代理模式 转服模式
流量路径 玩家 → CubeDock → 上游 玩家 → limbo → 目标服
上游要求 原生支持网易 RakNet v8 客户端可直连；资源包需匹配
目标看到的 IP CubeDock 侧连接 玩家真实 IP
资源包 由上游处理 limbo 预加载，仅未加密静态包
推荐场景 长期生产 · 兼容网易上游 大厅入口 · 静态包 · 真实 IP

从克隆到开房

Windows 使用一键构建脚本；其他平台按 README 手动构建。Node.js 用于控制台前端，未安装时构建脚本会提示。

Windows · PowerShell 
git clone https://github.com/emuyx/CubeDock.git
cd CubeDock
.\scripts\build.ps1
.\build\CubeDock.exe

首次打开控制台会要求创建管理员账号和密码；控制台默认 http://127.0.0.1:18321/。

Linux / macOS 
git clone https://github.com/emuyx/CubeDock.git
cd CubeDock
mkdir -p build/bin
go build -trimpath -o build/bin/CubeDockMain ./cmd/cubedock
(cd limbo && go build -trimpath -o ../build/bin/limbo .)
mkdir -p cmd/cubedock-launcher/payload
cp build/bin/CubeDockMain build/bin/limbo cmd/cubedock-launcher/payload/
go build -trimpath -o build/CubeDock ./cmd/cubedock-launcher
rm -f cmd/cubedock-launcher/payload/CubeDockMain cmd/cubedock-launcher/payload/limbo
./build/CubeDock

需要 Go 1.25+ 与 Node.js 24；前端构建见 README。

上游要求： 无论代理还是转服，服务器都必须原生支持网易 RakNet v8；标准 BDS 不能直接使用。 转服模式的目标服务器由客户端直连，但仍需资源包匹配，且客户端能访问目标。
USAGE

从构建到开房

构建只是第一步；下面是构建完成后的实际使用顺序。

  1. 01

    启动并登录控制台

    运行 CubeDock.exe（或 build/bin/CubeDockMain），打开终端显示的地址。默认 http://127.0.0.1:18321/；首次打开时在本机创建管理员账号和密码，之后用这个账号登录。

  2. 02

    完成全局设置

    在「设置」确认控制台端口、limbo 程序路径和是否自动启动全部房间。服务器、房间、资源包和提示页面属于配置方案，在下一步单独编辑。

  3. 03

    创建配置方案

    进入「配置方案」新建或复制方案，填写连接方式、服务器地址、房间名、人数、准入等级、标签、好友准入和资源包设置。无论代理还是转服，服务器都必须原生支持网易 RakNet v8。

  4. 04

    添加网易账号

    进入「账号与房间」→「添加网易账号」，选择配置方案，使用互通版邮箱直登或导入 sauth。每个账号对应一个房间；同一账号不能重复添加，账号数量不设固定上限。

  5. 05

    启动房间

    在「账号与房间」或侧边栏账号入口打开账号仪表盘，单独「启动 / 停止 / 重连」。房间进入 online 后，房间号会显示在「本地联机房间」卡片中；主页的全局启动/停止会作用于全部账号。

  6. 06

    手机加入

    在网易版 Minecraft 客户端打开「本地联机」，刷新后加入刚创建的房间。玩家流量会经 CubeDock 转发到上游；在上游看到的身份由配置方案决定。

  7. 07

    转服模式（可选）

    在「配置方案」把连接方式改为「转服模式」，配置中转房间地址/端口、limbo 提示页面和资源包，保存后重新启动该账号的房间。玩家会先进入本地中转房间，看到提示页面后再进入你的服务器。当前只覆盖未加密、静态资源包。

  8. 08

    管理玩家、房间成员与好友

    代理模式下可在「控制台」使用 list 查看玩家、kick <ID|名称> 断开玩家，并用 transfer 注入 Transfer（POC）。玩家弹窗的「网易房间成员」标签可踢出等待中的玩家；账号仪表盘可手动同意好友申请。停止房间会结束房主机器人和 limbo。

FAQ

常见问题

完整 FAQ 也在控制台的「常见问题」页面、使用文档 和 README 中。

代理模式和转服模式有什么区别？分别适合什么场景？

代理模式（默认）：玩家经 CubeDock 中继到上游，登录链重签、游戏包直通。适合上游原生支持网易 RakNet v8、希望长期稳定中继、需要上游看到网易身份、或不想运行 limbo 的场景。

转服模式：玩家先进入 limbo 预加载资源包并显示表单，点击后直连目标服务器。适合客户端能直连目标、资源包未加密且静态、希望目标看到真实 IP/延迟，或需要 limbo 大厅入口的场景。目标有资源包时必须与 limbo 预加载的一致；加密/动态包不适合。

配置方案、账号和房间是什么关系？

配置方案保存服务器、房间、资源包和 limbo 提示页面设置；账号在添加时选择一套方案，并获得独立的房间 runtime。一个账号只能有一个房间；多个账号可以共用同一方案，也可以使用不同方案。切换账号的方案需要先停止全部房间，切换后下次启动该账号的房间时生效。

房间踢人和世界玩家踢人有什么区别？

「已进入世界」标签断开的是已经进入上游世界的玩家；「网易房间成员」标签踢出的是 TanLobby 房间成员，包含已进房但还没进入世界的玩家。房间踢出依赖 dockerB transfer 节点；踢出不会封禁，玩家仍可能重新加入，除非房间设置了仅好友、密码或准入等级。

认证链为什么不再使用 AGPL 组件？

当前认证链由 internal/netease 第一方实现，覆盖 PE 认证、用户资料、transfer 节点选择和房主凭据派生。vendor-src/g79client、internal/funauth 已删除，发布包也不再生成 SOURCE/；第三方许可文本仍随包分发。

标准 Bedrock Dedicated Server 能直接作为上游吗？

两种模式都不能直接使用标准 BDS：服务器必须原生支持网易 RakNet v8。转服模式只是让客户端直连目标，同样不会把网易协议翻译成标准 Bedrock；此外还要求客户端能访问目标、资源包与 limbo 一致。

手机看不到房间 / 开房失败怎么办？

确认账号可以正常登录、没有在其他设备上登录，房间已经显示为在线。若返回 1351，打开验证链接完成验证，再回到页面点一次「登录并添加」；CubeDock 不会自动重试。

玩家进房后马上断开？

玩家刚进房就断开：先检查服务器是否支持网易协议、版本是否接近、资源包是否一致；转服模式还要确认玩家能直连服务器。仍失败时可在诊断页复制报告。

资源包不下载 / 转服时报资源包错误？

网易客户端会忽略 ResourcePacksInfo，limbo 默认用 netease 模式强制 SendPacks，并在最后一包后补发 Stack。确认资源包目录正确、包与目标服务器一致；加密包/动态包不支持。ResourcePackStack 后主动断开是拉包流程的预期行为。

控制台打不开 / 忘记管理员密码？

默认地址是 http://127.0.0.1:18321/。首次启动时在本机控制台创建管理员账号和密码；初始化只允许本机。忘记密码需停止程序、备份并删除数据目录中的 admin.json，重启后重新创建。控制台只允许白名单 Host/Origin，/api/session/* 只允许本机访问。

一个网易账号能开多个房间吗？

不能。同一账号重复登录会使已有房间掉线。每个账号对应一个房间；账号数量不设固定上限，实际数量受机器资源与网易限制。

数据文件在哪里？会把账号提交到仓库吗？

数据默认在程序数据目录：config.json、room-tokens.dat、accounts.json、interop-device.dat、admin.json、logs/。Windows 使用 DPAPI 保护会话，其他平台使用 0600 文件；不要提交这些文件。
